# Архитектура

## Компоненты

- `MainActivity` — первичная QR-привязка телефона, PIN/TOTP-вход родителя, управление лимитом с пульта, выбор приложений, launcher-профиля, Device Admin/Owner и безопасное обновление.
- `AppSelectionActivity` — изолированный прокручиваемый экран запускаемых приложений; сохраняет выбранные package ID непосредственно при Back, не раздувая основной экран настроек.
- `LimiterAccessibilityService` — получает только события смены активного окна, ведёт секундный heartbeat, учитывает время, защищает опасные системные экраны и создаёт timer/blocker accessibility overlays.
- `ConfigStore` — приватные настройки, TOTP-секрет, PIN-хеш, текущий день, использованное и дополнительное время.
- `PinHasher` — PBKDF2-HMAC-SHA1 с 20 000 итераций, случайной 128-битной солью и сравнением хешей без раннего выхода. Старые записи на 150 000 итераций проверяются один раз в фоне и автоматически мигрируют.
- `TotpAuthenticator`, `QrCodeRenderer` — уникальный 160-битный Base32-секрет, стандартный `otpauth://` QR и локальная HMAC-SHA1-проверка текущего плюс девяти предыдущих 30-секундных окон. Коды не сохраняются и не накапливаются.
- Повторный показ QR всегда использует сохранённый действующий секрет, поэтому несколько телефонов родителей получают одинаковый TOTP-аккаунт и остаются совместимыми друг с другом.
- `LauncherProfileManager` — атомарно включает одну из трёх заранее объявленных launcher-алиасов с разными названиями, иконками и TV-баннерами.
- `DeviceOwnerProtection` — если приложение назначено Device Owner, включает системный запрет удаления собственного package ID; USB-восстановление снимает этот режим.
- `AppScope`, `LimitMath`, `DayKey` — чистая логика выбора пакетов, границ/форматирования времени и локального календарного дня.
- `BootReceiver` — один раз после загрузки обновляет дневное состояние. Он не запускает Activity или отдельный сервис.
- `UsbRecoveryReceiver` — принимает только системные USB/media-события, отличает съёмное хранилище от внутреннего и очищает конфигурацию.
- `GithubUpdateClient`, `UpdateVerifier` — читают последний стабильный GitHub Release и до установки сверяют SHA-256, package ID, версию и сертификат подписи APK.
- `TimerDeviceAdminReceiver` — компонент Device Admin и точка явного ADB-назначения Device Owner; само приложение не может выдать себе эти права.

## Поток данных

1. На чистой установке создаётся случайный TOTP-секрет и показывается локальный QR для телефона родителя.
2. Родитель сохраняет резервный PIN, лимит и область контроля.
3. После явного согласия Android открывает системную страницу, где родитель включает accessibility-службу.
4. Служба получает имя пакета при смене окна. Иерархия View и текст окна не запрашиваются.
5. Heartbeat учитывает монотонное `elapsedRealtime` только при активном экране, отсутствии заставки и совпадении пакета с областью контроля.
6. Накопленная дельта фиксируется на диске не реже чем раз в пять секунд и при выключении экрана/остановке службы.
7. Пока остаток положительный, служба показывает маленький таймер. При нуле он заменяется полноэкранным чёрным overlay с локальной PIN/TOTP-проверкой.
8. После проверки применяется выбранное по умолчанию продление либо показывается выбор 10/15/20/30/40/60 минут. Бонус относится только к текущему локальному дню.

## Персистентность

Все значения хранятся в одном приватном `SharedPreferences`. Backup и device transfer выключены. При смене локальной даты использованное и дополнительное время сбрасываются. Для активной сессии используется монотонное время, поэтому изменение настенных часов не создаёт отрицательную дельту; смена календарной даты всё равно зависит от системных даты и часового пояса.

При аварийном отключении питания может потеряться не более последнего интервала записи, то есть до пяти секунд. После перезагрузки Android сам переподключает включённую accessibility-службу; receiver не пытается бесконечно запускать её вручную.

## Границы безопасности

- В обычной установке это локальный родительский барьер. После явного ADB-назначения Device Owner системно запрещает удаление пакета.
- PIN не хранится открытым текстом, но короткий четырёхзначный PIN имеет ограниченную энтропию. PBKDF2 замедляет офлайн-перебор.
- USB — намеренно слабый аварийный ключ по требованию продукта: любое распознанное подключение может удалить PIN и настройки.
- Receiver не экспортирован другим приложениям. Внутреннее/эмулированное хранилище не считается USB-восстановлением.
- Служба не читает дерево окон и не перехватывает ввод. Она закрывает весь системный пакет настроек/установщика, пока родитель не открыл двухминутное окно обслуживания. Сеть использует только `MainActivity` после ручной проверки обновления.
- Обновлятор принимает APK только из релиза заданного репозитория, проверяет digest GitHub и локально сравнивает сертификат с уже установленным приложением.
- Ошибка добавления overlay использует ограниченный exponential backoff до 60 секунд, а не плотный retry-loop.

## Совместимость

Используются только платформенные Android API без AndroidX UI-зависимостей. Это уменьшает APK и число конфликтов. OEM может изменить доставку accessibility/USB-событий, порядок окон или политику фоновой работы; поэтому итоговая проверка нужна хотя бы на одной целевой модели каждого производителя.

## Тестирование и выпуск

Unit-тесты проверяют PIN, TOTP и его пятиминутную границу, варианты продления, launcher-профили, арифметику лимита, фильтрацию пакетов и USB-политику. Android Lint проверяет manifest/API/TV-ресурсы. `assembleDebug` создаёт устанавливаемый debug APK. Публичный release требует выбранного package ID, закрытого release-keystore и теста на реальном телевизоре; signing material хранится вне репозитория.
